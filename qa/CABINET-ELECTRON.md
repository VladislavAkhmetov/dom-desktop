# Отчёт: подключение кабинетов к Electron и проверка Portable-сборки

С 23 октября 2026 отдельный portable кабинетов не выпускается. Текущий файл один: `release\dombro-<version>-Portable.exe` (сейчас `dombro-0.0.1-Portable.exe`). Режим кабинетов включён в нём по умолчанию. Ниже — отчёт от 10 октября 2026, когда пилот ещё собирался вторым exe.

**Дата:** 10 октября 2026 г.  
**Проект:** dombro (`D:\dev\tools\browser`)  
**ОС:** Windows 11 x64  
**Итоговый артефакт:** `release\dombro-cabinet-0.1.0-Portable.exe` (103.4 МБ)

---

## 1. Цель и контекст задачи

Перенести согласованный пилот пространств («Кабинетов») из веб-прототипа в нативное приложение Electron для Windows 11 с сохранением всей функциональности, структуры данных и согласованной навигации:
1. Запуск в нативном окружении Electron с настоящими веб-страницами через `WebContentsView` и системным открытием локальных документов.
2. Полная изоляция профиля пилота от основного приложения `dombro` (отдельная база данных SQLite, Vault, Chromium cache, cookies и single-instance lock).
3. Автоматический запуск портативной сборки в режиме кабинетов без необходимости передавать аргументы командной строки вручную.
4. Долговременная сохранность миграции `upgradeCabinets` в SQLite при повторных запусках.
5. Корректная работа фоновых обоев интерфейса в упакованном приложении (протокол `file://`).
6. Комплекс нативных тестов и верификация собранного исполняемого файла.

---

## 2. Архитектура изоляции и режим запуска

### Автоматическое определение режима
Режим кабинетов (`isCabinetPilot`) определяется на уровне главного процесса (`electron/main.cjs`):
- Флаг командной строки `--cabinet-pilot`;
- Переменная окружения `DOM_CABINET_PILOT=1`;
- Имя исполняемого файла содержит `cabinet` (например, `dombro-cabinet.exe`);
- Портативная переменная Electron `PORTABLE_EXECUTABLE_FILE` содержит `cabinet`.

Благодаря этому созданная портативная сборка `dombro-cabinet-0.1.0-Portable.exe` запускается в режиме кабинетов **напрямую по двойному клику без ручного ввода параметров**.

### Изоляция профиля и хранилищ
До вызова `app.requestSingleInstanceLock()` и создания хранилища устанавливается изолированный каталог пользователя:
- **Путь к профилю:** `%APPDATA%\dombro-cabinet-pilot`
- **База данных SQLite:** `%APPDATA%\dombro-cabinet-pilot\dom.sqlite`
- **Резервная копия:** `%APPDATA%\dombro-cabinet-pilot\dom.previous.sqlite`
- **Ключи и пароли:** `%APPDATA%\dombro-cabinet-pilot\secrets.encrypted.json` (защищены Windows `safeStorage`)
- **Браузерная сессия:** `persist:dom-cabinet-browser` (изолированные cookies, LocalStorage, кеш и история сайтов)
- **Single-instance lock:** независим от основного `dombro`. Приложение в стандартном режиме и пилот кабинетов могут работать параллельно без взаимных блокировок.

## 3. Миграция данных и SQLite-персистентность

1. **Ленивая инициализация IndexedDB:**  
   В `src/bridge.ts` устранена eager-инициализация веб-базы данных на этапе загрузки модуля. При работе в Electron веб-хранилище IndexedDB не создаётся, всё состояние обслуживается через нативный IPC и SQLite worker.
2. **Персистентность миграции:**  
   В `src/statePersistence.ts` при загрузке данных в режиме пилота проверяется версия схемы `cabinetVersion !== 1`. Если база ещё не мигрирована, вызывается `upgradeCabinets(value)` и дельта изменений немедленно сохраняется в SQLite через `bridge.applyChanges(changes)`. При последующих запусках состояние считывается уже в структуре кабинетов.
3. **Идемпотентность:**  
   Повторные чтения не дублируют кабинеты и не сбрасывают сохранённые материалы.

## 4. Согласованная навигация и UX

| Сценарий | Ожидаемое поведение | Реализация в Electron |
|---|---|---|
| **Дашборд: выбор кабинета** | Остаётся внутри каркаса дашборда; браузер не разворачивается во весь экран | Подтверждено: `.app-shell:not(.browsing)` сохраняется, `.hub-ambient` и dock на месте |
| **Дашборд: кнопка «+»** | Создаёт пустой кабинет внутри дашборда без диалогов ввода имени | Подтверждено: кабинет создаётся мгновенно, имя подбирается автоматически, режим не переключается |
| **Дашборд: «Продолжить»** | Открывает кабинет внутри дашборда; внешние программы и браузер автоматически не стартуют | Подтверждено: материалы и вкладки готовы, открытие происходит только по явному выбору |
| **Явный переход в браузер** | Кнопка «Открыть вкладки» / выбор вкладки раскрывает браузерный каркас | Подтверждено: активируется `.app-shell.browsing`, отображается `.workstage-container` и панель `BrowserChrome` |
| **Браузер: кнопка «+»** | Создаёт кабинет с чистой вкладкой и фокусом в адресной строке | Подтверждено: пользователь остаётся в браузерном режиме с готовым полем ввода адреса |
| **Возврат из браузера** | Возвращает пользователя в предыдущий раздел дашборда | Подтверждено: скрывает WebContentsView, исключая перекрытие интерфейса дашборда |

## 5. Настоящие вкладки и документы

- **WebContentsView:**  
  Вкладки открывают реальные веб-страницы в изолированной партиции `persist:dom-cabinet-browser`. Поддерживаются навигация, фавиконки, заголовки, масштабирование и управление bounds при открытии боковых панелей дня и материалов.
- **Скрытие нативных страниц:**  
  При переходе в дашборд `BrowserManager.hide()` скрывает WebContentsView, гарантируя отсутствие артефактов поверх карточек дашборда, диалоговых окон и меню.
- **Локальные документы:**  
  В десктопном режиме кнопка «Документ» обращается к системному диалогу выбора файла (`bridge.pickResource('file')`). Путь к файлу сохраняется в ресурсах кабинета. Нажатие на документ запускает системную ассоциацию по умолчанию через `bridge.openResource` (`shell.openPath`).
- **Геолокация и системные разрешения (Chrome-style In-Browser Prompt):**  
  * В `electron/main.cjs` включён нативный флаг Chromium `WinSystemLocationProvider` (`app.commandLine.appendSwitch`), обеспечивающий доступ к системной службе геолокации Windows 10/11 без необходимости передачи проприетарного Google API ключа.
  * Для доверенной сессии приложения (`session.defaultSession`) разрешены `geolocation` и `notifications`.
  * **Красивый запрос разрешений в стиле Google Chrome:** стандартный системный диалог Windows (`dialog.showMessageBox`) заменён на элегантный бабл `PermissionPrompt.tsx`, прикреплённый непосредственно под омнибоксом (адресной строкой) браузера.
  * Бабл отображает фавиконку/иконку разрешения (геолокация, микрофон, камера, уведомления), точный домен сайта, понятное описание («Сайт запрашивает доступ к данным о вашем местоположении») и кнопки «Разрешить», «Блокировать», а также кнопку закрытия `(X)` и поддержку клавиши `Escape`.
  * Интеграция с нативным `WebContentsView`: при появлении диалога через MutationObserver временно активируется защита (`bridge.browser.block(true)`), делая бабл видимым поверх нативной страницы без графических артефактов компоновщика.
  * Ответ пользователя через IPC `bridge.browser.respondPermission(id, allowed)` возвращается в `BrowserManager.profile.setPermissionRequestHandler`, после чего Chromium передаёт координаты веб-странице (`navigator.geolocation.getCurrentPosition`). Реальная выдача координат проверена в нативном окружении Windows.

## 6. Фоновые изображения (обои)

- **Проблема на `file://`:**  
  В упакованном приложении абсолютные пути CSS вида `/backgrounds/abstract-hills.jpg` разрешались в корень диска (`file:///backgrounds/...`), из-за чего фон становился сплошным цветом.
- **Решение:**  
  Реализована функция `resolveWallpaperUrl(url)` в `src/WallpaperPicker.tsx`, которая для протокола `file://` строит относительный путь к текущему каталогу приложения. В `src/styles.css` базовое значение переведено на относительный URL.
- **Входящие обои:**  
  Все фоны («Волны: Полдень», «Волны: Рассвет», «Волны: Сумерки», «Классический луг») скопированы в дистрибутив `dist/backgrounds/` и проверены в сборке.

## 9. Инструкция по запуску

### Запуск готовой Portable-сборки (рекомендуется)
Файл расположен по пути:
```powershell
.\release\dombro-cabinet-0.1.0-Portable.exe
```
*Запуск не требует прав администратора, установки или предустановленного Node.js. Все зависимости и нативный модуль SQLite упакованы внутри.*

### Запуск распакованной сборки
```powershell
.\release\win-unpacked\dombro-cabinet.exe
```

### Запуск из исходного кода в режиме разработки
```powershell
npm run dev:cabinet
```
*(Запускает Vite и Electron с изолированным профилем кабинетов)*

### Повторный запуск тестов
```powershell
npm run test:cabinet-native
```

### Возврат к стандартной версии
Основная версия приложения `dombro` запускается через `npm run dev` или `npm run start` (или запуск `release\dombro-0.1.0-Portable.exe` / передача флага `--legacy-pilot`) и использует стандартный каталог данных `%APPDATA%\dombro`. Профиль пилота кабинетов (`%APPDATA%\dombro-cabinet-pilot`) полностью изолирован и не влияет на основную версию.

## 10. Известные ограничения

1. **Ленивая загрузка вкладок (Lazy Loading):** При открытии кабинета со множеством сохранённых вкладок (100–300 шт.) живые `WebContentsView` создаются только по мере их явного просмотра. Это защищает от исчерпания системной памяти при старте.
2. **Локальные документы:** В материалах сохраняются системные пути к исходным файлам, а не их содержимое. Открытие документа происходит через системную программу по умолчанию (`shell.openPath`). В пилоте отсутствует прямое редактирование Office/PSD файлов внутри окна Electron и нет автоматического закрытия сторонних редакторов при смене кабинета.
3. **Кнопка «Продолжить»:** Фокусирует выбранный кабинет внутри дашборда. Она намеренно не выполняет пакетный запуск всех десктопных приложений и браузерных окон сразу, сохраняя управляемость процессом.
4. **Вне рамок пилота:** Синхронизация между устройствами, локальные LLM/ИИ, авто-выгрузка фоновых страниц с потерей несохранённых веб-форм и сборка под macOS на данном этапе не подключались (зарезервированы под следующие этапы согласно `docs/cabinet-upgrade.md`).
