# Правила и инструкции для ИИ-ассистентов (AI Guidelines)

> **Критическое требование:** Любой ИИ-агент (Antigravity, Cursor, Claude, Copilot, ChatGPT и др.), работающий в этом репозитории, **ОБЯЗАН** соблюдать изложенные ниже правила.

---

## 1. Правило синхронизации документации (Doc Sync Rule)

Каждое изменение в кодовой базе должно быть отражено в документации:
1. **При добавлении нового функционала или изменении логики:**
   * Обнови [`ARCHITECTURE.md`](ARCHITECTURE.md) — добавь описание системы, архитектурных связей и деталей реализации.
   * Обнови [`README.md`](README.md) — если изменилось поведение для пользователя, способы запуска или ключевые возможности.
   * Отметь статус в [`IMPLEMENTATION.md`](IMPLEMENTATION.md) — переведи пункт из `[ ]` в `[x]` или добавь новый этап.
2. **Если создана новая подсистема или сложный модуль:**
   * Создай или дополни спецификацию в папке `docs/` (например, `docs/your-feature.md`).
   * Добавь ссылку на новый документ в карту документации в [`ARCHITECTURE.md`](ARCHITECTURE.md).

---

## 2. Честность технического статуса (No Hallucinations / No Marketing Speak)

* **Никогда не выдавай мок за реальную реализацию:** Если адаптер написан на тестовых данных (как, например, захардкоженные примеры RSS или тестовые ответы без живого OAuth), прямо фиксируй это в коде и документах.
* **Никаких маркетинговых клише:** В описаниях, комментариях и документации пиши понятным инженерным языком без пафоса («революционный», «инновационный», «знакомо ли вам?»). Описывай конкретную механику, ограничения и поведение в граничных случаях.

---

## 3. Архитектурные правила проекта

1. **Изоляция Electron:**
   * Никакого `nodeIntegration: true` в окнах рендеринга.
   * Любое общение UI с системой — только через `window.dom` ([`src/bridge.ts`](src/bridge.ts)) и прелоад [`electron/preload.cjs`](electron/preload.cjs).
   * Все IPC-вызовы в главном процессе должны валидироваться через `trustedHandle`.
2. **Память и жизненный цикл вкладок:**
   * Не ломай механизм выгрузки неактивных пространств (`park`).
   * Вкладка с активным аудиопотоком (`isCurrentlyAudible()`) или несохраненным пользовательским вводом (`dirty`) **всегда** должна оставаться защищенной (`record.protected = true`).
   * Не убирай zero-flicker кэширование скриншотов (`tabCovers` / `.native-cover`).
3. **Безопасность данных (Local-first & Encryption):**
   * Все токены, пароли и секреты должны шифроваться системным `safeStorage`.
   * Пользовательские данные должны сохраняться транзакционно в SQLite. Поврежденный файл состояния не должен перезаписываться пустым.
4. **Спокойный интерфейс и борьба с когнитивной перегрузкой (Calm Tech):**
   * **Цель продукта:** снятие тревожности и информационного перегруза с людей, которые тонут в сотнях вкладок и теряют концентрацию.
   * **Типографика и читаемость:** крупная, чистая гарнитура Manrope, комфортные интервалы, достаточный воздух. Запрещено использовать мелкий, слепой текст (мельче 12px) или плотные свалки данных.
   * **Минимум пояснений в UI (Self-evident design):** интерфейс должен объяснять себя сам через положение, иконки и отклик. Запрещено загромождать экраны длинными обучающими плашками, туториалами и подсказками-бабблами.
   * **Устранение триггеров тревоги:** никаких красных бейджей с количеством непрочитанного, никаких таймеров просрочки, никаких бесконечных новостных лент.
   * **Мягкая кинематика:** анимации короткие, функциональные, без отскоков и рывков, строго с поддержкой `prefers-reduced-motion`. Длительности и кривые — только токены ДНК из `src/motion.css` / `src/motion.ts` ([docs/motion.md](docs/motion.md)); наведение и нажатие ничего не двигают и не масштабируют; появление — `calm-in`. Соблюдение проверяет `tests/motion-dna.test.ts`.
   * **Таблица стилей:** цвета, поверхности, линии, скругления, тени и размеры — только роли из `src/tokens.css`; кнопки, плашки, поля и меню — классы из `src/controls.css` ([docs/design-tokens.md](docs/design-tokens.md)). Контекст меняет размер, но не цвет, скругление и состояния. Проверяет `tests/design-tokens.test.tsx`.
   * **Безопасность прерываний:** пользователь никогда не должен бояться закрыть окно или переключить задачу. Всё сохраняется автоматически в SQLite, а незаполненные формы защищены от выгрузки.

## 4. Обязательная проверка перед завершением задачи

Перед тем как сообщить пользователю об успешном выполнении работы, **обязательно** выполни проверку:

```powershell
# 1. Проверка типов и сборка
npm run build

# 2. Запуск полного набора unit-тестов и проверок SQLite
npm test

# 3. При изменении нативного браузера или Electron-части — запуск нативных тестов
npm run test:cabinet-native
```

Если тесты падают или сборка завершается с ошибкой — исправь причину перед отчётом.

## 5. Правила версионирования и сборки Electron (Release & Versioning Rules)

1. **Система нумерации версий:**
   * Единственный номер — поле `version` в `package.json`. Сейчас это `0.0.1`. Следующий выпуск меняет только этот номер, например `0.0.2`.
   * Отдельной подписи `0.001` нет. В интерфейсе и прелоадере версия показывается как `v` плюс `app.getVersion()`.
2. **Синхронизация с прелоадером (Splash screen):**
   * Прелоадер [`electron/splash.html`](electron/splash.html) получает версию из главного процесса [`electron/main.cjs`](electron/main.cjs) через параметр запроса `?v=` на базе `app.getVersion()`.
   * Запасной текст `#splash-version` совпадает с текущей версией (`v0.0.1`), пока параметр не подставился.
3. **Именование артефактов сборки:**
   * Портативная сборка — один файл: `dombro-${version}-Portable.exe` (сейчас `dombro-0.0.1-Portable.exe`).
   * Второй копии с другим написанием версии нет. Отдельный `dombro-cabinet-…-Portable.exe` не собирается: режим кабинетов уже включён в этом exe.
   * Установщик NSIS, если он нужен отдельно: `dombro-Setup-${version}.exe`.
4. **Обновления:** сами обновляются только установки NSIS (`electron-updater`). Portable лишь сообщает о новой версии. Канал выпусков задан в `electron-builder.json → publish` и `electron/updates.cjs → RELEASES` — менять оба вместе (см. [`docs/release-and-updates.md`](docs/release-and-updates.md)). Выпуск — только через тег и GitHub Actions.
4. **Команды сборки:**
   ```powershell
   # Один портативный файл: release/dombro-<version>-Portable.exe
   npm run dist:portable

   # Сборка распакованного каталога:
   npm run pack

   # Верификация упакованного бинарника:
   node scripts/verify-portable-live.cjs
   ```
