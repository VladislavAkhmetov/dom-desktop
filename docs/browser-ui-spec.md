# Браузинг Дома: UI и ТЗ на дальнейшую интеграцию

Дата: 2 октября 2026. Основа — вариант «Пульс дня».

## 1. Результат и границы

Браузинг сохраняет связь с днём: справа от адреса постоянно виден один актуальный сигнал, по нажатию открываются события, дела и фокус. Страница и панель дня делят доступную область. Сохранение страницы позволяет выбрать общие закладки, группу закладок или пространство.

UI реализован в приложении. Существующие обработчики навигации, вкладок, задач, календаря, фокуса и ИИ подключены. Закладки и группы также сохраняются через общее хранилище. Это не экран с вымышленными счётчиками. Раздел 8 описывает оставшуюся работу; его пункты не следует считать уже реализованными.

Общие закладки используют материалы служебного пространства `kind: 'web'`. Материалы проекта остаются в соответствующем пространстве. Отдельной копии календаря, списка задач или базы закладок UI не создаёт.

## 2. Компоновка

Сверху вниз:

1. Верхняя панель: Дом, текущий контекст, назад/вперёд/обновить, адрес, сохранение страницы, пульс дня, меню Дома.
2. Лента вкладок: вкладки текущего дела, плюс, «Вкладки» со счётчиком, действия с вкладками.
3. Страница или новая вкладка. Справа при необходимости — «Мой день».

Общий визуальный язык: Manrope, существующие цвета текста и акцента, полупрозрачные поверхности и фон приложения. Контекст, пульс и обзор вкладок имеют текстовые подписи. Редкие действия находятся в меню.

| Ширина окна | Поведение |
| --- | --- |
| Более 1200 px | Верхняя панель в одну строку; панель дня 340 px |
| 961–1200 px | Компактный логотип; панель дня 310 px |
| 701–960 px | Навигация и адрес переходят на отдельную строку; панель дня 290 px |
| До 700 px | Пульс занимает отдельную строку; панель дня располагается над страницей, высота не более 48dvh, содержимое прокручивается |

Базовая высота верхней панели — 68 px, адреса и пульса — 42 px. В Windows предусмотрено место под системные кнопки окна. Эти размеры описывают текущий CSS, а не фиксированную высоту для всех платформ.

В проектной новой вкладке показаны следующий шаг текущего дела, если он задан, и материалы пространства. В обычном браузинге показаны закладки. Сначала выводятся шесть материалов; «Показать все» раскрывает остальные. Выбор ссылки в пустой вкладке использует эту вкладку.

## 4. Быстрое сохранение страницы

### Пользовательский сценарий

1. Пользователь нажимает закладку справа в адресе или Ctrl/Cmd + D.
2. Открывается компактная панель «Сохранить страницу»: URL, название, выбор «Закладки / Пространство», назначение и кнопка сохранения.
3. В «Закладках» доступны «Без группы», существующие группы и «Новая группа». В «Пространстве» — список доступных неархивных пространств.
4. После успешной записи панель закрывается, появляется сообщение с местом сохранения. Открытая вкладка, её пространство и введённые на странице данные не изменяются.

Первоначально выбирается последнее успешно использованное место. Если его нет — текущее проектное пространство; для обычного браузинга — общие закладки. Фокус сразу на основной кнопке: повторное сохранение выполняется сочетанием Ctrl/Cmd + D, Enter.

Кнопка закладки видна и на пустой вкладке, но недоступна с подсказкой «Сначала откройте страницу». Галочка означает, что URL уже присутствует в одном из доступных мест. Она не блокирует сохранение в другое место.

### Правила данных

| Объект | Поля и назначение |
| --- | --- |
| Ссылка | Существующий `Resource`, `kind: 'link'`, `id`, `name`, `target`, `createdAt` |
| Принадлежность группе | Необязательное `Resource.bookmarkGroupId`; отсутствие означает «Без группы» |
| Группы | `Space.bookmarkGroups: { id, name }[]` у служебного пространства браузинга |
| Последнее место | `AppState.lastBookmarkDestination: { spaceId, groupId? }` |
| Общие закладки в запросе UI | Значение `spaceId: '@bookmarks'`; адаптер преобразует его в реальное служебное пространство |

Старые данные без новых полей остаются корректными. Идентификаторы ресурсов и групп генерируются независимо от названия. Новая группа и ссылка записываются одним изменением состояния. Состояние сохраняется существующим механизмом: SQLite в Electron, IndexedDB в веб-режиме; режим `?demo=1` использует отдельные демонстрационные данные в sessionStorage.

Дубли определяются по полному HTTP/HTTPS URL внутри назначения. В закладках назначение включает группу, поэтому один URL можно сохранить в разных группах. В проекте один URL не создаёт повторный материал. Параметры запроса и фрагмент URL сохраняются.

При уже существующей ссылке показано «Страница уже сохранена здесь», её название доступно только для чтения, основная кнопка — «Готово». Этот экран не является редактором существующей закладки. При вводе имени новой группы существующее совпадение без учёта регистра используется повторно. Название группы ограничено 80 символами, новой ссылки — 200.

### Ошибки и жизненный цикл

- Пока идёт запись, поля и повторное сохранение заблокированы. Панель не закрывается по Escape или клику снаружи до ответа хранения.
- При ошибке остаются введённые название, группа и назначение; показана ошибка и доступен повтор.
- Сохранение в исчезнувшее/архивное пространство или исчезнувшую группу отклоняется с понятной ошибкой.
- Если запомненное назначение недоступно при следующем открытии, выбирается допустимое место; исчезнувшая группа заменяется «Без группы».
- Открытие панели фиксирует снимок URL и заголовка выбранной вкладки. Последующий редирект не подменяет сохраняемый адрес без ведома пользователя.
- Отмена до сохранения не создаёт группу или ссылку.
- Сохранение ссылки не переносит и не закрывает вкладку. Перенос живой вкладки выполняется существующей командой «Перенести» в меню вкладки или перетаскиванием.

### Где найти сохранённое

Общие закладки: обычный браузинг → новая вкладка → «Закладки». При наличии групп доступен фильтр «Все закладки / Без группы / название группы». Материалы проекта: меню контекста → «Материалы пространства», либо соответствующее пространство в дашборде. Общий поиск Дома продолжает находить ссылки как материалы.

В этой версии группы имеют один уровень. Переименование, удаление, вложенность, массовое перемещение закладок и импорт структуры папок в эту модель ещё не реализованы.

## 5. Пульс и панель дня

### Источники и приоритет

`browserDayModel(state, now, focus)` — адаптер представления над общим состоянием. Он использует `selectAttention`, `remindersForDay`, `realEvents` и `zenTimer`.

Порядок выбора основного сигнала:

1. Сигнал из общего `selectAttention`: наступившее напоминание → событие в его интервале уведомления → активный фокус → важное письмо. Применяются существующие правила свежести и скрытия.
2. Завершённый фокус.
3. Ближайшее текущее или предстоящее событие сегодня, если уведомление о нём не скрыто.
4. «Мой день» с количеством сегодняшних дел, остатком с прошлых дней или пустым состоянием. При ошибке календарной подписки в этом состоянии указано, что календарь требует внимания.

В пульсе две строки: главное состояние и его контекст. Скрытое уведомление не возвращается в пульс через резервный выбор ближайшего события. Само событие остаётся в списке дня. Сигналы фоновых запросов ИИ и музыки в текущую модель не включены.

### Содержимое панели

| Блок | Текущая реализация | Действие |
| --- | --- | --- |
| Ближайшее | До трёх незавершившихся событий сегодня, включая события на весь день | Встреча по URL, материалы связанного пространства, календарь |
| Сегодня | До пяти незавершённых дел; наступившее напоминание дополнительно выводится, даже если не запланировано на сегодня | Завершение, ссылка на все дела |
| С прошлых дней | Количество незавершённых дел с прошедшей плановой датой | Переход на «Мой день» |
| Важное письмо | Письмо, если именно оно выбрано общим механизмом внимания | Открытие оригинала |
| Фокус | Текущее состояние таймера и выбранное дело | Существующая панель фокуса |
| Добавить дело | Текст до 500 символов, плановая дата — сегодня, без автоматического срока/таймера | `saveCapture(title, null, localDate(now), 'task')` |
| Записать мысль | Отдельный путь записи | Существующая форма Capture |
| Спросить ИИ | Существующий ассистент | Контекст не отправляется автоматически |
| Открыть дашборд | Главная «Мой день» | `returnHome` |

Завершение дела обновляет общий `AppState`, поэтому результат виден в дашборде. Используется существующая отмена завершения. Пока запрос записи выполняется, повторные действия с делами заблокированы. При ошибке добавления текст остаётся в поле; при ошибке завершения механизм хранения откатывает оптимистическое изменение.

Даты интерпретируются в локальной зоне приложения. У событий на весь день дата окончания исключительная: событие с окончанием 2 октября не показывается 2 октября. Закончившиеся встречи и события следующего дня не попадают в список оставшегося дня. Сбой календарной синхронизации не стирает прежние события; панель явно сообщает о сохранённых данных.

### Открытие и закрепление

Панель открывается только по действию пользователя. Новое уведомление меняет пульс, но не раскрывает панель и не переводит фокус автоматически. Без закрепления панель закрывается при уходе из браузинга. С закреплением остаётся открытой при возвращении в браузинг в текущем запуске. Явное закрытие снимает закрепление.

Escape внутри незакреплённой панели закрывает её. В закреплённой панели Escape её не закрывает. После явного закрытия фокус возвращается к пульсу. Закрепление и черновик поля дела сейчас не сохраняются между перезапусками; черновик поля дела также теряется при размонтировании панели.

## 7. Electron, клавиатура и ограничения веб-режима

Панель дня — сосед `.workstage-canvas`, не модальный слой. ResizeObserver в `NativePane` пересчитывает область WebContentsView. Открытие панели должно уменьшать ширину страницы без перезагрузки и без вызова блокировки страницы. Это относится и к двум страницам рядом.

Меню и диалоги используют существующую блокировку WebContentsView, чтобы нативный сайт не перекрывал интерфейс. Панель сохранения является диалогом; в Electron на время её показа действует этот механизм. Страница не уничтожается. Дальнейшее улучшение визуального фона диалога описано в разделе 8.

Клавиатура: Ctrl/Cmd + L — адрес; D — сохранение страницы; T — новая вкладка; W — закрыть вкладку; Shift + T — восстановить закрытую; Tab — переключить вкладку; Shift + A — Стол; K — общий поиск. Нативная страница передаёт D, как и другие браузерные сочетания, через `before-input-event`.

Диалог сохранения поддерживает фокус на основной кнопке, Tab/Shift + Tab, Escape и возврат фокуса. Поля адреса, добавления дела и названий учитывают IME composition: подтверждение состава текста не отправляет форму.

В веб-режиме произвольный внешний сайт не встраивается как в Electron. Используется существующее предложение открыть его во внешней вкладке. Назад/вперёд/обновить для нативной страницы в этом режиме недоступны. Визуальная проверка страницы рядом с панелью выполнялась на локальной странице `public/prototype/weekend.html`; это не проверка произвольного внешнего сайта.

## 8. ТЗ на оставшуюся привязку и доработки

### P0 — перед приёмкой нативного браузинга

**NAV-01. Достоверное состояние навигации.**

Сейчас кнопки назад и вперёд активны при наличии нативной страницы; UI не получает сведения о доступной истории. Расширить существующий поток событий `NativeBrowserEvent` состоянием `tabId`, `canGoBack`, `canGoForward`, `isLoading`. Источник — соответствующий WebContents. Обновлять при создании страницы, начале/окончании загрузки, переходе по истории, навигации внутри страницы и ошибке. Не записывать эти эфемерные значения в постоянную модель материалов.

Критерий: у новой страницы «Назад» недоступна; после перехода доступна; после возврата доступна «Вперёд». Загрузка и остановка отображаются по состоянию активного `tabId`. Событие от фоновой вкладки не меняет кнопки активной. Редирект обновляет адрес, но не затирает текущий пользовательский ввод.

**NATIVE-01. Приёмка геометрии и сохранности живой страницы.**

Расширенный `tests/browser-native.cjs` уже прошёл в скрытом Electron на отдельном тестовом профиле: открытая форма с текстом, открытие/закрытие панели дня, просмотр рядом, смена пространства, Ctrl + D и возврат из диалога сохранения. Перед выпуском дополнительно повторить сценарии при изменении масштаба дисплея и на целевых платформах.

Критерий: нативная страница не перекрывает панель дня и не оставляет свободную полосу после её закрытия; введённый текст остаётся; панель дня не выставляет `manager.blocked`; диалог сохранения корректно скрывает и возвращает нативные представления.

### P1 — завершение повседневных сценариев

**DAY-01. Сохранение предпочтения и черновика.** Вынести закрепление панели в пользовательскую настройку с безопасным значением по умолчанию. Черновик добавления дела хранить отдельно от постоянных задач до успешной записи. Не сохранять пустые задачи ради восстановления поля.

Критерий: закрытие/повторное открытие панели и переход в дашборд не теряют введённый текст; успешная запись очищает черновик; закрепление восстанавливается после перезапуска; явное закрытие снимает его.

**BOOKMARK-01. Управление группами и закладками.** Добавить переименование и удаление групп, переименование/удаление/перемещение сохранённых ссылок. При удалении группы предлагать сохранение её ссылок в «Без группы»; удаление самих ссылок должно быть отдельным явным выбором. При переносе в группу с тем же URL объединять записи без создания дубля. Использовать существующие идентификаторы ресурсов и общую транзакцию.

Критерий: нет ссылок на несуществующую группу; перенос не меняет живую вкладку; изменения доступны после перезапуска; отмена восстанавливает только затронутые записи и не стирает параллельные изменения. Вложенные группы — отдельное расширение модели, не часть текущего одноуровневого UI.

**BOOKMARK-02. Поиск назначения при большом числе мест.** При большом списке пространств/групп заменить обычный select на доступный combobox с локальным поиском и клавиатурным выбором. Сохранить текущий контракт `SavePageRequest`. Стрелки выбирают вариант, Enter подтверждает выбор, Escape закрывает список, следующий Escape — панель.

**BOOKMARK-03. Завершение пути добавления с новой вкладки.** Текущая «+ Ссылка» использует прежнюю форму добавления ресурса и сохраняет в пространство без группы. Передать выбранную группу в эту форму либо переиспользовать выбор назначения после ввода URL. Критерий: добавление ссылки из открытой группы кладёт её в эту группу и сразу показывает в списке.

**ATTENTION-01. Единый контракт внимания.** При добавлении новых типов сигналов расширять общую модель, которую используют и дашборд, и браузинг. Утвердить значения для выполняющегося/ошибочного фонового ИИ и музыки перед добавлением кнопок. Не показывать паузу фокуса без поддержки паузы самим таймером.

Критерий: одинаковые данные дают одинаковый главный сигнал на обоих экранах; скрытие или завершение применяется в обоих; фоновая ошибка не выдаётся за успешное завершение. Завершение действия не открывает панель самопроизвольно.

**NATIVE-02. Фон компактного диалога.** Если скрытие WebContentsView при сохранении визуально убирает сайт, на время диалога показывать последний снимок страницы под ним. Не создавать новую страницу ради снимка. Альтернатива — отдельная компоновка с изменением границ нативной области. Решение проверять на реальном Electron, включая два WebContentsView рядом.

### Порядок выполнения

Сначала NAV-01 и NATIVE-01, затем сохранение черновика и предпочтений, управление закладками и путь «+ Ссылка», после — новые типы внимания и визуальное улучшение нативного диалога. Все обработчики подключать через существующие props и адаптеры; повторная сборка экрана или отдельное состояние дня не нужны.
