# Быстродействие: путь изменения данных, память вкладок, бандл

Что сделано, почему и как проверять. Код: [`shared/state.js`](../shared/state.js), [`electron/storage-worker.cjs`](../electron/storage-worker.cjs), [`electron/storage.cjs`](../electron/storage.cjs), [`electron/tab-memory.cjs`](../electron/tab-memory.cjs), [`src/App.tsx`](../src/App.tsx).

## Путь одного изменения

Любое изменение — заголовок вкладки, переход, прокрутка, ввод в блокнот — идёт так:
интерфейс `commit()` → `diffState` → IPC `state:apply` → главный процесс → поток хранилища → SQLite.

| Шаг | Было | Стало |
|---|---|---|
| `applyChanges` (интерфейс и поток) | `structuredClone` всего состояния на каждый вызов | Копируются только контейнеры на пути изменения, остальные ветки переиспользуются. Входное состояние не меняется (тест в `tests/state.test.ts`) |
| Чтение в потоке | `read()`: `SELECT` + `JSON.parse` всей базы на каждый `apply` и `get` | Состояние в памяти потока (`cache`); поток — единственный писатель. `read()` только при запуске |
| Запись коллекций | Каждая изменённая коллекция переписывалась целиком: `JSON.stringify` всех пространств или всей истории | Пишутся только сущности из путей `[коллекция, '@id', …]`; при вставке/удалении/перестановке обновляются только номера позиций (`UPDATE … ordinal`), без сериализации. Целиком — только если коллекция заменена полностью |
| Поисковый индекс FTS5 | Полная перестройка внутри каждой «поисковой» записи | Одна перестройка через 400 мс после последнего изменения и при запуске; запрос поиска и резервная копия сначала сбрасывают отложенную перестройку |
| Главный процесс | `storage.get()` уходил в поток (каждые 15 с — `checkReminders`, плюс интеграции) | Обёртка `storage.cjs` держит последнее состояние; `get()` ждёт только незавершённые записи |
| Пересылка в интерфейс | Состояние уходило окну-отправителю дважды: ответом на `state:apply` и рассылкой `state:changed` | Рассылка идёт только другим окнам (`broadcastState(state, except)`) |

Порядок, вставки и удаления после перезапуска проверяет `tests/storage.cjs` (`npm test` → `scripts/test-storage.cjs`).

## Сигнал «поверх страницы открыт диалог»

`MutationObserver` на всём `document.body` раньше на **каждое** изменение DOM делал `querySelector` и IPC `browser.block`. Теперь проверка одна за кадр (`requestAnimationFrame`), а IPC уходит только когда ответ меняется.

## Память вкладок (Memory Saver)

`electron/tab-memory.cjs → idleTabs`, раз в минуту из `BrowserManager.discardIdle()`:

* скрытая вкладка без защиты выгружается через **30 минут**;
* живыми в фоне остаются не больше **12** скрытых вкладок, старейшие сверх лимита выгружаются сразу;
* защищённые (ввод в форму, воспроизведение, звук) и видимые не трогаются; страница, которая просит остаться (`beforeunload`), остаётся.

Вкладка из сессии не пропадает: URL, позиция прокрутки и снимок остаются, при возврате страница создаётся заново и показывает снимок до загрузки (zero-flicker). Парковка пространства (`park`) работает как раньше.

## Бандл интерфейса

Разбор `vite build` по пакетам (до изменений, КБ без gzip): React DOM ~398, `App.tsx` ~287, motion ~136, `ical.js` ~79, `Home` ~73, `PasswordSettings` ~55, lucide ~50.

* `ical.js` теперь грузится только при синхронизации календаря (`useCalendarSync` → `import('./calendar/parse')`; диапазон дат вынесен в `calendar/range.ts`). Основной чанк: 1 617 → 1 540 КБ.
* Удалена неиспользуемая зависимость `@fontsource/inter`.
* **Не сделано осознанно:** `React.lazy` для настроек, ассистента, истории. Electron читает файлы с диска, выигрыш — разбор ~150 КБ при запуске; при этом тесты, открывающие эти разделы через `App`, начинают зависеть от асинхронной загрузки модуля. Вернуться, когда `App.tsx` будет разделён на модули.

## Что ещё можно ускорить

* Снимки вкладок (`tabCovers`) лежат в состоянии `App`: каждый новый снимок перерисовывает всё приложение. Вынести в отдельный store с подпиской.
* `App.tsx` (2 200+ строк, 50+ `useState`) — любое изменение состояния перерисовывает дерево; разделение на модули с `memo` даст больше, чем ленивая загрузка.
* CSS: 34 файла, ~490 КБ, слоями перекрывают друг друга. Постепенно переносить в `card-system.css` и удалять старое.
