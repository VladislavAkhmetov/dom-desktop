# Модель безопасности dombro

Что защищаем, где проходят границы доверия и что остаётся открытым. Код: [`electron/main.cjs`](../electron/main.cjs), [`electron/browser.cjs`](../electron/browser.cjs), [`electron/vault.cjs`](../electron/vault.cjs), [`electron/approved-paths.cjs`](../electron/approved-paths.cjs), [`electron/network.cjs`](../electron/network.cjs). Выпуск и fuses — в [`release-and-updates.md`](release-and-updates.md).

## Границы доверия

| Зона | Доверие | Чем ограничена |
|---|---|---|
| Главный процесс (Node) | Полное | — |
| Интерфейс dombro (`dist/index.html`) | Доверенный, но **не хранитель секретов** | `sandbox`, `contextIsolation`, CSP `script-src 'self'`; IPC только через `trustedHandle` (отправитель, главный фрейм, адрес `dist/index.html`) |
| Вкладки сайтов (`WebContentsView`) | Недоверенные | Отдельная сессия `persist:dom-…-browser`, `sandbox`, только `http/https`, ошибки сертификатов отклоняются, новые окна → вкладки, page-preload ничего не выставляет странице |

Принцип для интерфейса: даже если в нём выполнится чужой код (уязвимость в зависимости, XSS из ленты новостей), он не должен получить пароли целиком, запустить произвольную программу или ходить в локальную сеть.

## Пароли

* В интерфейс уходят только сводки `CredentialSummary` (`id`, `origin`, `username`, `title`) — без паролей (`vault:credentials:list`).
* Список на странице сайта — **точное совпадение хоста** (`www.` игнорируется). Раньше поиск шёл подстрокой: на `a.com` показывались записи `data.com`.
* Автозаполнение: интерфейс передаёт `credentialId`, главный процесс сам берёт запись и отдаёт её странице, только если хост записи совпадает с хостом страницы (`Vault.credentialFor`).
* Предложение сохранить пароль: перехваченный на странице пароль остаётся в главном процессе (`BrowserManager.passwordOffers`, 10 минут, не больше 20, очищаются при закрытии вкладки). Интерфейс получает токен; `vault:credentials:save-offer(token, username, password?)`. Поле пароля в окне «Сохранить пароль?» пустое: пусто — сохранить введённый на странице, иначе — то, что ввели здесь.
* Настройки: «показать» и «скопировать» запрашивают один пароль по `id` (`vault:credentials:reveal`). Экспорт CSV пишет главный процесс через диалог сохранения (`vault:credentials:export`).
* На диске — `secrets.encrypted.json`, шифрование `safeStorage` (DPAPI/Keychain), без открытого запасного варианта.

## Локальные файлы и программы

`shell.openPath` открывает документы **и запускает программы**. Состояние приложения интерфейс пишет сам (`state:apply`), поэтому путь из состояния доверенным не считается.

* `ApprovedPaths` (`userData/approved-paths.json`, недоступен через `state:apply`) — пути, пришедшие через главный процесс: окно выбора файла (`resource:pick`), список недавних файлов Windows, список открытых окон (путь exe), сочетание Ctrl+Shift+S.
* При первом запуске этой версии один раз принимаются все `file`/`app`/`window`-ресурсы, которые уже были сохранены пользователем (`adopt`).
* `resource:open` (файл, программа, запасной путь окна) и `material:read` (чтение текста для ИИ) работают только с одобренными путями. Иначе — сообщение «Этот файл добавлен не через окно выбора. Добавьте его заново».
* Ссылки (`link`) открываются системным браузером только для `http`, `https`, `figma`.
* IPC управления окнами Windows принимает только дескрипторы вида `0x…` (до 500 в списке) — до нативной библиотеки `koffi` ничего другого не доходит.

## Сеть

* Ленты RSS, календари iCal и чтение сохранённых ссылок идут через `fetchPublic`: только `http/https` без логина в адресе, не больше 5 МБ, не дольше 25 с; адреса этого компьютера и частных сетей (`localhost`, `127/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10`, `::1`, `fc00::/7`, `fe80::/10`, `*.local`) отклоняются. Перенаправления проходят вручную, каждый шаг проверяется заново.
* Gmail, ИИ и проверка обновлений ходят на фиксированные адреса (`fetchLimited`).
* **Подсказки поиска** (Google Suggest) выключены по умолчанию — «Настройки → Подсказки поиска от Google» (`state.searchSuggestions`). Даже включённые, они не отправляют ввод, похожий на адрес, путь, почту или токен (есть `/ \ : @`, вид `что-то.что-то`, одно слово от 24 символов).

## Сайты во вкладках

* **Разрешения** (камера/микрофон, геолокация, уведомления, чтение буфера) спрашиваются у пользователя. Решение «запомнить» хранится по **источнику** (`https://site.example|media`) в `userData/site-permissions.json` и переживает перезапуск. Раньше ключом было имя хоста: `http` и `https` делили одно решение, и всё забывалось при выходе. Остальные разрешения (USB, Bluetooth, HID, Serial, захват экрана, File System Access) отклоняются без вопроса.
* **Загрузки исполняемых файлов** (`.exe`, `.msi`, `.bat`, `.cmd`, `.ps1`, `.vbs`, `.js`, `.lnk`, `.scr`, `.hta`, `.reg`, `.jar`, …) — один вопрос перед сохранением, по умолчанию «Не скачивать».
* **Общая защита `web-contents-created`**: любое новое `webContents` не может подключить `<webview>`, а новые окна запрещены, пока конкретное окно не задаст свой обработчик.

## Осознанные решения

* **Маскировка под Chrome.** Вкладки отправляют `Sec-CH-UA` с брендом «Google Chrome», из `User-Agent` убирается `Electron/…`, включён `disable-blink-features=AutomationControlled`. Без этого вход в Google и проверки Cloudflare часто отказывают встроенным браузерам. Цена: сайты не знают, что это не Chrome. Решение принято сознательно; при проблемах с политиками Google — пересмотреть.
* **Нет Safe Browsing.** В Electron нет встроенной защиты Google от фишинга и вредоносных загрузок. Частично помогают блокировщик Ghostery (списки трекеров и части вредоносных доменов) и вопрос перед загрузкой исполняемых файлов. Полноценная проверка ссылок не реализована.

## Что остаётся открытым

* Интерфейс по-прежнему может прочитать **один** пароль за вызов `vault:credentials:reveal` (так работают «показать» и «скопировать» в настройках). Подтверждения паролем Windows, как в Chrome, нет.
* `fetchPublic` проверяет имя хоста буквально; публичное имя, которое резолвится в частный адрес (DNS rebinding), не ловится.
* Пути, одобренные один раз, остаются одобренными; удаление ресурса из пространства не отзывает одобрение.
* Подписи кода нет (см. `release-and-updates.md`).
